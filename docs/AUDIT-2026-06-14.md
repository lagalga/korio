## Metodología

Tres pasadas paralelas con agentes Explore sobre `api/`, `src/`, `supabase/`,
`tests/` y `ui/`:

1. **Seguridad** — auth/RLS, inyección, exposición de secretos, CORS, validación de inputs.
2. **Diseño** — multi-tenancy, contratos de error, duplicación, sync FalkorDB↔Postgres, config sprawl, async/sync, singletons.
3. **Bugs / runtime hazards** — race conditions, manejo de errores, leaks, off-by-one, null safety, timezone.

Total: **21 hallazgos** (4 CRIT, 3 HIGH, 8 MED, 6 LOW). Cruzados contra el roadmap
(`docs/MCP-SERVER.md` §Phase 8, `docs/MULTI-TENANT-INGESTION.md`,
`docs/CHAT-PIPELINE-GUARDRAILS.md`, `docs/PHASE-10-MULTIMODAL-INGESTION.md`,
Phase 9 notes en docs internos) para no duplicar trabajo ya previsto.

| Fichero | Cambio |
|---|---|

Variables de entorno nuevas:

- `KORIO_ENV=prod` (default) — `dev` añade `localhost` a la whitelist CORS.
- `KORIO_EXTRA_CORS_ORIGINS` — orígenes adicionales coma-separados.
- `KORIO_ADMIN_TENANT_ID` — UUID del tenant al que pertenece el admin global; si no se setea, el check de tenant en `DELETE /document` queda inactivo (compatibilidad atrás).

## Verificación end-to-end aplicada

- `pytest tests/ -v` → 28+ tests, sin regresiones.
- `scripts/benchmark.py -n 5` → sin regresión vs p50=1983ms.
- CORS: `curl -i -H "Origin: https://evil.test" https://korio.es/health` → sin header permisivo.
- Cross-tenant DELETE: con admin key válida + UUID de doc en otro tenant → 404 + log warning.
- RLS: `SELECT * FROM mcp_api_keys` con role `anon` → 0 filas.
- Embedder con modelo equivocado → arranque aborta con mensaje claro.
- `/upload` con Mistral KO → `/tmp/tmp*` no crece.
